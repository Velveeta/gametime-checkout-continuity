# Agent operating contract

Build a focused, production-shaped **prototype**, not a checkout platform. Next.js App Router + React 19 + TypeScript strict + Tailwind 4 + shadcn/ui/Radix + TanStack Query + Upstash Redis + Zod + Vitest; Playwright for a small E2E slice. Vercel target. One canonical responsive `/checkout/[sessionId]` route, no separate mobile route. Server Components for first meaningful HTML; small client islands for actions, polling, countdown and menus. Domain/services must not import Next.js, React, or Redis clients.

**Authoritative state:** Redis-backed sessions, inventory, reservations and orders. Never rely on process memory, client clock, or Redis expiry notifications for correctness. All mutations use service-layer invariants and atomic Redis operations (Lua scripts or carefully justified transactions). Monetary values integer cents, timezone-aware ISO timestamps, server-time synchronization. No actual payment/auth/inventory integration.

**Key semantics:** reservation immediately hides seats from other carts; business deadline is fixed unless explicitly changed by developer action; ordinary requests do NOT extend the inventory hold. Atomic completion claim before deadline protects an in-flight payment under a separate processing deadline. One order per checkout; retry only confirmed transient failures, at most three total attempts. Price increase blocks until exact current quote version acknowledged; decrease auto-applies with positive messaging. Completed sessions cannot be reopened at checkout. Existing mounted page expiring redirects to event; fresh navigation to expired URL attempts idempotent re-reservation using current availability and price. Recovery metadata outlives reservation.

**Agent discipline:** implement only current wave; do not expand scope or install dependencies without justification. Add tests for behavior touched. Do not rewrite stable prior waves for aesthetics. No hardcoded fake success paths in production-facing APIs. Developer routes are clearly demo-only and guarded against use outside configured demo mode; destructive reset requires confirmation. Prefer accessible, responsive, polished UI, not heavy animation. No secrets in repo. Maintain meaningful README notes. After every wave, run checks, commit if git is available, and write concise `handoffs/NN-*.md` (max 350 words). Stop for review.

**Reading budget:** this file + assigned wave + latest handoff only. Open specific source files as needed. Never read every prior spec or entire repository just to orient. In handoffs, cite file paths and decisions rather than pasting source code.
