# Wave 02 — checkout state machine and services

**Read:** `AGENTS.md`, this wave, latest handoff; inspect domain contracts by path.

Implement framework-independent checkout application services with injected repositories, inventory, payment stub, clock and analytics. Default reservation hold 10 minutes; retention 30 minutes **after** expiration (configurable); payment processing deadline independent, e.g. 60 seconds. Start timer at successful atomic reservation, not page load. Ordinary mutations do not extend hold. Demo deadline mutation is explicit and atomic; server clock determines all deadlines. Include server timestamp in state responses for clock-offset display.

Quote versioning: increased **total** blocks completion until user acknowledges exact current quote version; decreased total auto-applies and emits good-news event; never charge more than acknowledged. Any quote update invalidates obsolete acknowledgement as needed. Use cents. Price changes may be demo-induced. Payment stub resolves deterministically within seconds: success, definitive decline (nonretryable), transient timeout/unavailability (retryable only after stub conclusively resolves non-capture). Max 3 **total** payment attempts; exhaustion terminal FAILED. Completion claim is atomic against session state, quote version, deadline, reservation ownership and unique order constraint. Concurrent different idempotency keys must not create two orders. Repeated same-key requests return stable result. PROCESSING protected from reservation expiry, but processing timeout must be reconciled into a safe state before releasing inventory; document prototype assumptions.

Recovery: `getSession` is read-only and never creates a new session. Separate `recoverExpiredSession` invoked only on **fresh checkout navigation**; if expired metadata exists and listing/quantity available, atomically create ONE successor session and fresh hold at current price; concurrent recoveries return same successor. If unavailable, redirect to event; missing metadata to root. An **already-mounted page** seeing expiry redirects to event without recovery. Completed checkout redirects to root on later navigation/other devices; initiating caller alone receives confirmation capability/URL. Confirmation route is refreshable and scoped to that capability (demo token, not production auth).

**Tests:** transition table, deadline boundary, quote changes both directions, stale acceptance, 3-attempt retry, decline, timeout resolution, competing completion, competing recovery, no implicit extension, completion-vs-expiration race. Handoff `handoffs/02-checkout-domain.md`.
